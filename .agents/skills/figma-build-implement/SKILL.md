# L99 Figma Build + Implementation

Load for every Figma, creator-studio, design-system, design-to-code, visual QA, component mapping, or production-artifact UI task.

## Tool skills

- `figma-use` is mandatory before every Figma write.
- Load `figma-generate-library` for variables, tokens, reusable components, variants, themes, or libraries.
- Use `figma-generate-design` only for first capture of a running web surface into an existing file; rebuild editable structure with `figma-use`.
- Use `figma-code-connect` only for published components with exact node URLs, eligible plan access, and verified code matches.

## Repository profile

- Product: story and artifact production engine with creator/studio, video, review, provenance, event, and promotion surfaces.
- Preserve the root runtime and `story-engine/` boundaries; inspect the current UI framework and component paths before implementation.
- Primary design targets: creator workspace, Story Memory and canon review, artifact inspection, video/shot planning, style/mode selection, event history, validation, release/promotion, and Control Room status.
- Figma may display synthetic story snippets and sanitized artifact metadata. It is not a canon store, event bus, artifact authority, renderer, or promotion gate.

## Required sequence

1. Run 5W1H and the repository founder stack.
2. Redteam the premise: canon drift, provider fantasy, fake render proof, tenant leakage, unbounded variants, and duplicated studio architecture.
3. Inspect current schemas, events, artifact contracts, UI code, render modes, visual styles, and existing Figma/library assets.
4. Lock the authoritative source revision, workspace/tenant boundary, target surface, states, implementation files, and proof.
5. Build foundations and reusable studio components before screens. Separate render mode, visual style, state, and provider capability instead of encoding them as one visual variant axis.
6. Implement inside the current runtime and reuse existing event, artifact, provenance, memory, and validation paths.
7. Redteam the selected implementation: stale revisions, missing source hashes, inaccessible error states, false final-render claims, secret exposure, promotion bypass, and rollback.
8. Verify with current unit/contract tests, artifact validators, promotion gates, Playwright, and synthetic evidence.
9. Report Figma nodes, code paths, contracts changed, proof, drift, rollback, and next founder approval.

## Data and authority boundary

- Do not place unpublished story text, creator-private content, tenant identifiers, provider credentials, payment data, notification data, or raw events into Figma.
- Use synthetic excerpts and redacted metadata.
- Do not label an animatic, mockup, style board, or manifest as final rendered media.
- Do not create a second event bus, memory source, provenance engine, artifact ledger, or promotion authority.

## Code Connect

Map only published reusable studio components whose code props and variant model are verified. Map every variant exhaustively. Do not connect one-off story frames, raw generated images, or artifact content as reusable code components.

## Definition of done

The editable design, canon/provenance boundary, implementation status, state coverage, accessibility, tests, artifact proof, unresolved differences, rollback, and next gate are recorded. A visual storyboard is not runtime or renderer proof.
